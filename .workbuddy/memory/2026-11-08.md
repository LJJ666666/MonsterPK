## P4-2d 玩家对战 1v1 实现（2026-11-08）

**杰哥「好，继续。」→ 承接 P4-2d 玩家对战 1v1**。目标：四类玩法第三块——玩家互相对战，战斗态挂房间态（不新增权威源）、双方意图服务端仲裁、结算写双方档各一次。

**①不新增状态域**：1v1 战斗态挂 `RoomState.pvp`（`sides: [PvpSide, PvpSide]` 双方镜像，各自「敌人」=对方 active），复用房间内核 `submitIntent` / `advanceTurn` / `tick` / `autoSubmit` 驱动回合，不另起回合同步机制。写个人档仍是 `commitState()` 唯一入口；`withRoomLock(roomId)` 串行。

**②纯函数 `game/pvp.ts`**：`createPvpState`（镜像化 + PP + 活体校验）、`applyPvpTurn(state, actions, rng)`（优先度/速度先手 → `applySideAction` 双方结算 → 回合末伤害 → 自动换人 → 判胜负，**复用 `rules.ts` 全部战斗公式**、RNG 注入可单测）、`parsePvpIntent`/`encodePvpIntent`/`pickPvpIntent`/`pvpViewFor`。

**③意图编码**：`move:<moveId>` / `switch:<0..5>` / `flee`；房间内核 intent 正则放宽 `^[A-Za-z0-9_:\-]+$`（只加冒号），不破坏既有 kernel E2E。`pvpViewFor(state, viewerUserId)` 按接收者裁剪：己方完整队伍（含 moveIds/六维/PP）、对方仅 active 公开信息（specId/hp/status），不泄露对方未上场成员与技能 PP。

**④结算**：`settlePvpRoom` 写双方档各一次 `commitState(source='battle')`、各自 CAS/revision 不互相覆盖、`pvpSettled` 标记幂等；**只回写 HP/异常，不发经验/金钱/捕获**（奖励/排位分归台账 F15）；`maybeSettlePvp` 在 `applyRoomIntent`/`tickRoom`/`sweepRooms` 三处调用（胜负既可能在手动交齐也可能在超时代放）；`room.ts`↔`pvp.ts` 循环依赖用动态 `import('./pvp')` 规避。

**⑤接口**：`POST /api/pvp/create`（建房）/ `POST /api/pvp/:roomId/join`（加入，满员 active 时生成 PvpState 并 `attachPvp`）；伪上报 `winner`/`hp`/`damage`/`fled` → 400 `PVP_INPUT_FORBIDDEN`；无队伍 404 `PVP_NO_PARTY`、无 WS 409 `ROOM_WS_REQUIRED`、越权 `roomId` 404、满员 join 409。

**⑥前端**：`lib/pvp.ts`（`pvpViewOf`/`newNonce`/文案）、`lib/sessionState.ts`（`PvpView` 类型）、`lib/api.ts`（`pvpCreate`/`pvpJoin`/`roomAction`）、`components/PvpModal.tsx`（创建/加入/订阅 `room.state`/渲染双方 HP/日志/发意图）、`Camp.tsx` 第二行「对战」入口。
