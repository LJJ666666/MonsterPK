### 最终架构（混合方案，勿回退）
- **proot Debian 13 trixie**（glibc 2.41 + openssl 3.5）只跑 Node 后端——因为 Prisma 5.x engine 是 glibc 二进制，bionic 跑不了（11-18 已证死胡同）。
- **PG18/Redis8 用 Termux 原生**（127.0.0.1:5432/6379），不在 Debian 内重装。实测 proot 出方向能连原生端口；proot 内 `/sdcard` 直通可读写（Termux 私有 home 不直通）。
- **Node 用官方 glibc 二进制手工解压**（不是 apt）：`node-v20.19.2-linux-x64.tar.xz` 解压到 `/opt/node-v20`，自带 node20.19.2 + npm10.8.2 + openssl3.0.15。避开了 Debian apt 装 nodejs/npm 拖 210+ 包（g++/git/libicu 等）导致 40 分钟未装完的坑。

### 关键突破链（踩坑）
1. **proot-distro 5.10.3 安装 debian 失败**：新版改用 OCI registry（Docker Hub）+ Python urllib，设备 ping 不通 registry-1.docker.io → `Errno 101 Network unreachable`。**正解**：老版本 v4.29.0 的 `debian-trixie-x86_64-pd-v4.29.0.tar.xz`（35MB）经宿主机 gh-proxy 镜像下载（沙箱代理 4153 对 github release 返回 502，对 api.github.com 通；6799/8693 已失效），sha256 核对 `4b8f33b8...` 与官方一致，adb push → root cp 到私有目录 → `proot-distro install -n debian <FILE>` 从本地文件装（install 参数 `-n` 不是 `--alias`）。
2. **proot login 报 `ptrace(TRACEME): Permission denied`**：雷电 SELinux 下 run-as 上下文无 ptrace 权限。**正解**：用 root 跑（`su -c "export PATH=...; proot-distro login debian -- ..."`）；root shell 无 bash，脚本要用绝对 bash 路径。真机 Termux 无此问题。
3. **路径映射**：proot 内 `$HOME=/`，Termux 私有 home 不可见，但 **`/sdcard/mpk/` 直通可读可写**（root 身份）。后端包/node 包/脚本都放这里。
4. **npm/prisma**：NPM_CONFIG_ALLOW_REMOTE=all + registry=npmmirror（lock 里 121 个 npmmirror resolved URL）；npm10 无 npm12 的 allowScripts 破事；prisma generate 自动下 `libquery_engine-debian-openssl-3.0.x.so.node`，6 个 migration 全 apply。
5. **后端进程活不过 adb 会话（最关键）**：`nohup`/`setsid` 在 proot 内都无效——proot 用 ptrace 跟踪所有子进程，login 会话结束会统一清理。**正解**：Termux 层（proot 之外）用 `nohup setsid proot-distro login debian -- bash backend-guardian.sh &` 让整个 proot 会话后台常驻，guardian 脚本里后端**前台 exec** 不返回。root 执行后 proot 进程 PPID=1 被 init 收养，新 adb 会话 health 稳定 200。
