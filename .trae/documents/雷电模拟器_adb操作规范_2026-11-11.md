## 2. 五条铁律（盲点坐标误触推广位，会被静默装游戏）⭐

来源：06 篇 §12，2026-09-21 实测定论。当时 adb 调试期间模拟器**自己多装了两个游戏**
（`com.tanwan.rxjhjxly.ld` / `com.leniu.dpcqln.ld`），`firstInstallTime` 精确落在调试时间窗内。
根因：雷电桌面 `launcher3` 的**底部 Dock 整排是游戏推广位（ViewPager，可左右滑出更多）**，
点一下直接跳「雷电游戏中心」并触发下载；且推广位**会轮换**，记坐标完全没用。

| # | 规则 | 说明 |
|---|---|---|
| 1 | **点任何坐标前先查前台** | `adb -s emulator-5558 shell "dumpsys window displays \| grep mCurrentFocus"`，必须是 `com.monster.game/...` 才点。这是唯一硬标准 |
| 2 | 弹窗按钮坐标用 `uiautomator dump` 取，**别硬编码** | 弹窗位置会浮动 |
| 3 | **避开屏幕底部**：`y > 2500` 是 Dock 推广区 | 1260×2800 机型实测；任何「底部按钮」坐标都要单独验证 |
| 4 | 能用按键就别用坐标 | `input keyevent 4`（返回）能替掉大量「取消/关闭」点击 |
| 5 | 误入别的 App 立刻拉回，**别继续盲点** | `adb -s emulator-5558 shell "am start -n com.monster.game/.MainActivity"` |

> **一句话：桌面不是中性地板，桌面是广告位。**
> 本项目的 4 项 adb 补测全部走命令行（`am start -W` / `dumpsys gfxinfo` / `dumpsys meminfo` /
> `screencap` / `logcat`），**不需要任何 `input tap`**，从流程上就不触发这个坑。

## 3. 常用命令（本项目口径）

```bash
A="D:/game/leidian/LDPlayer14/adb.exe"
D="emulator-5558"
PKG="com.monster.game"
ACT="$PKG/.MainActivity"

# 设备 / 屏幕 / 前台
"$A" devices -l
"$A" -s $D shell "wm size; wm density"
"$A" -s $D shell "dumpsys window displays | grep mCurrentFocus"
"$A" -s $D shell "dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'"

# 安装 / 冷启动（带耗时）
"$A" -s $D install -r "E:/Six/MonsterPK/android/app/build/outputs/apk/debug/app-debug.apk"
"$A" -s $D shell "am start -W -n $ACT"          # 输出 TotalTime / WaitTime
"$A" -s $D shell "monkey -p $PKG -c android.intent.category.LAUNCHER 1"   # 等价点图标

# 截图 / 控件树 / 日志（取证三件套）
"$A" -s $D shell "screencap -p /sdcard/_s.png"; "$A" -s $D pull /sdcard/_s.png ./_s.png
"$A" -s $D shell "uiautomator dump /sdcard/_ui.xml"; "$A" -s $D pull /sdcard/_ui.xml ./_ui.xml
"$A" -s $D shell "logcat -c"; ...操作...; "$A" -s $D shell "logcat -d -v time" > _log.txt

# 性能
"$A" -s $D shell "dumpsys gfxinfo $PKG framestats"
"$A" -s $D shell "dumpsys meminfo $PKG"
```

**木桶细节**：
- 冷启动先 `logcat -c` 再操作，日志最干净；关键词 `FATAL` / `Exception` / `WebView` / `TypeError`。
- `input text` **只支持 ASCII**；中文路径 push/pull 必须**双引号包住**。
- `uiautomator dump` 抓不到悬浮窗，那种只能像素分析（本项目无悬浮窗 UI，用不上）。
- 脚本引擎/JS 的详细报错不一定进 logcat，配合 `screencap` 看屏幕。
- 调试残留别用 `rm -f /sdcard/_*`（会漏删无前缀探针）或 `rm -f /sdcard/*`（会误删系统目录）；
  用 03 篇 §11 的**白名单法**：导出 `ls -l` → 本地生成删除清单 → push → 逐行删。本项目补测只写
  `/sdcard/_mpk_*` 前缀文件，收尾按这个前缀精确清，不碰其它。

## 4. 构建链（本机重建，2026-11-11）

原仓库 `android/gradle/wrapper/gradle-wrapper.properties` 指向沙盒残留
`file:///workspace/gradle-8.14.3-all.zip`，本机不存在；`ANDROID_HOME` / `local.properties` 均无。
本机构建链落在 **E: 盘 NTFS**（不放 I:，见跨项目记忆）：

| 组件 | 路径 |
|---|---|
| Android SDK | `E:/Six/android-sdk`（platform-tools / platforms;android-36 / build-tools;35.0.0） |
| Gradle | `E:/Six/gradle-dist/gradle-8.14.3`（腾讯镜像 `gradle-8.14.3-bin.zip`，131 MB） |
| Gradle 缓存 | `E:/Six/gradle-user-home`（首次需拉 AGP 8.13 + androidx 约 330 MB，走代理约 7 分钟） |
| JDK | **必须 21**：Capacitor 8 / AGP 8.13 用 `sourceCompatibility 21`，本机 Temurin 17 会报 `错误: 无效的目标发行版: 21`（`apk_build_guide.md` §1 早已写明，本轮实测确认）。本次用华为云镜像的 OpenJDK 21 GA：`https://repo.huaweicloud.com/openjdk/21/openjdk-21_windows-x64_bin.zip`（192 MB / 33 秒），解压得 `E:/Six/jdk/jdk-21`（`javac 21`）。**不装系统、不改全局 `JAVA_HOME`**，仅构建时 export。⚠️ `aka.ms` 的 Microsoft JDK 21 实测仅 ~115 KB/s（192 MB 需 28 分钟），清华 Adoptium 镜像拒绝本网段，**别再走这两个源** |
| `android/local.properties` | `sdk.dir=E:/Six/android-sdk`（已被 `android/.gitignore` 忽略，**不入库**） |

构建时**绕过 wrapper**（避免把本机绝对路径写进入库文件），直接用解压后的 gradle 二进制，
并显式给 JVM 代理参数（Gradle 不读 `HTTP_PROXY` 环境变量）：

```bash
cd E:/Six/MonsterPK/android
export JAVA_HOME=E:/Six/jdk/jdk-21          # 必须 21，17 会编译失败
export ANDROID_HOME=E:/Six/android-sdk
export GRADLE_USER_HOME=E:/Six/gradle-user-home
GRADLE_OPTS="-Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=14777 \
             -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=14777" \
  /e/Six/gradle-dist/gradle-8.14.3/bin/gradle assembleDebug --no-daemon
```

产物：`android/app/build/outputs/apk/debug/app-debug.apk`（`*.apk` 已被 `.gitignore` 忽略，**不入库**）。

## 5. 调试包联网（仅本地自测，不进生产配置）

APK 是 Capacitor WebView 壳，前端静态资源在包内，但**业务数据全靠宿主机 3001 后端**。
三个必须同时满足的条件，缺一个就是白屏 / 登录失败：

| # | 约束 | 处理 |
|---|---|---|
| 1 | `API_BASE` 默认 `http://localhost:3001`，设备里 localhost 指向自己 | 构建期注入 `VITE_API_BASE=http://192.168.111.47:3001`，只影响 `dist/`（不入库） |
| 2 | WebView 默认 `https://localhost`，请求 `http://` 是 mixed content；Android 9+ 禁明文 | 生成的 `android/app/src/main/assets/capacitor.config.json`（已 gitignore）加 `server.androidScheme=http` / `cleartext=true` / `allowMixedContent=true`；`android/app/src/debug/AndroidManifest.xml` 加 `usesCleartextTraffic=true`（**debug sourceSet，release 不受影响**） |
| 3 | 后端 `CORS_ORIGIN` 只放行 `http://localhost:5173`，WebView origin 不匹配 | `.env`（不入库）追加 `http://localhost` 等；`backend/src/index.ts` 把 `CORS_ORIGIN` 按逗号拆数组传给 cors 插件，与 `wsProtocol.isOriginAllowed` 既有的 CSV 口径对齐 |

> ⚠️ 宿主机 IP 会随网络变化。换 WiFi 后需重新用新 IP 构建 `dist` 并 `cap sync`。
> **正式发布包（P5-3）不得使用上述明文 / 宽 CORS 配置**，届时改走 HTTPS 域名 + 生产 CORS 白名单。

## 7. 本轮实测新增踩坑（写 adb 脚本必须遵守）

1. **`gfxinfo` 静置采样恒 0 帧**：静态登录页静置 4s 是 `Total frames rendered: 0`，没有持续重绘。
   FPS 采样窗口必须覆盖「冷启动渲染」（`force-stop → am start -W → 3s`），并保留 0 帧静置对照，
   别把空数据当性能结果。
2. **雷电 `am start -W` 不输出 `ThisTime`**：冷启动与 resume 都只有 `TotalTime` / `WaitTime`；
   resume 还会打印 `Warning: Activity not started, its current task has been brought to the front`
   （`LaunchState: HOT`）。恢复耗时以 `TotalTime` 为准，别拿 `thisTime != null` 当成功判据。
3. **`adb pull` 的 `/sdcard/...` 会被 Git Bash 的 MSYS 路径转换改写**成
   `D:/software/.../PortableGit/sdcard/...`，报 `failed to stat remote object`；
   拉设备文件统一加 `MSYS_NO_PATHCONV=1`（或写 `//sdcard/...`）。
4. **构建链硬要求 JDK 21**（详见 §4）：Temurin 17 会报 `无效的目标发行版: 21`；
   `aka.ms` 的 Microsoft JDK 21 实测 ~115 KB/s，改用华为云镜像 192 MB / 33 秒。
5. **生产包里的广告角标不一定是雷电的**：`vite.config.ts` 曾挂
   `vite-plugin-trae-solo-badge`（`prodOnly:true` + `clickable:true` + 外链 trae.ai），
   会向 `dist/index.html` 注入可点击推广角标与一整段 `console.debug` 主题探测脚本
   （26,433 B → 卸载后 796 B）。已删除插件调用 + 卸载依赖。
   ⚠️ 与「雷电桌面 Dock 是广告位」区分：控件树里能抓到的才是应用内注入；抓不到、
   而 `dumpsys window` 显示 `SYSTEM_ALERT_WINDOW` 的属于其它应用悬浮层（如 `com.zdanjian.zdanjian` 自动精灵），
   全程不点即可，不影响 `dumpsys` 数据。
6. **`cap sync` 会被宿主安全删除拦截**（它要删已存在的生成目录）：本轮绕过方式是第一次 sync
   生成 `assets/public` 与插件目录后，前端重建直接用
   `cp -r dist/. android/app/src/main/assets/public/` **覆盖式同步**（不删目录）；
   `capacitor.config.json` 的 server 段单独 patch（该文件已 gitignore）。
