### 步骤 4 — 起双服务 + 探活


```bash
FRONT_PORT=${MPK_FRONT_PORT:-5173}
curl -s --noproxy '*' -o /dev/null -w "front:%{http_code}\n" "http://127.0.0.1:$FRONT_PORT/"
curl -s --noproxy '*' -o /dev/null -w "back:%{http_code}\n"  http://127.0.0.1:3001/api/health
```


**默认口径就是 `--strict`**：前后端都在线、0 跳过、服务缺失直接判 FAIL。明确离线才用 `--only=check,unit,docs --strict` 或 `--allow-missing-services`；`--skip=smoke` 只用于显式排查，**禁止当默认**（曾长期静默 SKIP 却仍报 VERIFY_OK）。

## 7. 红线（今天别踩）

1. **不把 `.env` / keystore / `secrets.env` 入库或贴聊天**；`git add -A` 前确认无 `.env`、`*.db`、`*.p12`。
2. **不用 exFAT U 盘**传记忆或重要文件；传前后各算一次 `sha256sum`。
3. **不默认 `--skip=smoke`**；`verify` 全量就用 `-- --strict`，离线才用 `--only=check,unit,docs --strict`。
4. **不在命令行传 `--host` / `--port`** 覆盖 `devConfig.mjs`；换端口用 `MPK_FRONT_PORT` 且同一 shell 里前后端与 verify 一致。
5. **工具链先一条命令核实再用**，不靠等待构建、不猜「应该在下载」；构建成功只认**产物时间戳 + bundle 内容**，不认后台任务退出码或日志尾。
6. **不擅自改产品语义**（规则 / 数值 / 风控 / 离线策略）；P1~P5 等杰哥拍板。工程实现取舍 tx 自行决定。
7. **不为兼容留后门 / 旧链路 / 开关**；开发期没有真实老用户，该删直接删干净。
8. **注入代理 env 分三层**，沙箱值禁写仓库；本地探活 `curl --noproxy '*'`，E2E 用 `127.0.0.1`，WS `ORIGIN` 用 `localhost`。
9. **git push 在沙箱内最多原样重试 5 次**（不换代理 / 不试直连 / 不改 config），仍失败交本机 `push-mpk.bat`；Git 状态汇报只给一句话。
10. **verify 偶发红先看 `.verify-logs/<runId>/`**，别直接重跑掩盖；带 RNG 的 E2E 要重试到终态。

## 9. 卡住了怎么办

| 现象 | 处置 |
|---|---|
| `clone` 401/403 | GitHub HTTPS 要 PAT / 凭据管理器 / `gh auth login`，不能用账号密码 |
| `fetch` 502 / `schannel` | `git config --local http.version HTTP/1.1`（只写本机）；只读探活 `git ls-remote` |
| 沙箱内 `push` 恒 502 | 最多 5 次原样重试，仍失败交本机 `push-mpk.bat`（`fetch` + `push master --tags`，不含 add/commit） |
| PG / Redis 没起 | 杰哥双击仓库外的 `start-mpk-runtime.bat`；tx 只探活、明确告知，不顶替 |
| `curl` 探活 502 但服务明明在 | 全局代理连 localhost 也拦 → `curl --noproxy '*'`；E2E 用 `127.0.0.1` 不用 `localhost` |
| `verify` 大面积红 | 先看 `.verify-logs/<runId>/index.json` 与失败阶段日志；服务没起会判 FAIL（不是代码 bug） |
| 起服务报 `exit 4` / `0xC0000142` | 宿主回收后台进程，不是程序 bug；先探活端口，无 LISTEN 再重启双服务 |
| 注册接口 `P2022` / 新字段不存在 | 漏 `npx prisma migrate deploy` 或 `npx prisma generate`；改 schema 前先停 :3001 |
| 「还没有存档，请先开始游戏」 | 全新空库正常：重新注册 + `grant` 授权；换账号残留旧渲染副本的 bug 已修（bug_log §74） |
| 工作树不干净 / 有本地 ahead 提交 | 先 `git status -sb` 核清楚，**别 `reset --hard`**；确认远端是否需要它 |
