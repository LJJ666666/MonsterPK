## 产品缺陷修复：幻兽个体值区间 + money 风控码语义（杰哥拍板）

**动机**：杰哥指出「幻兽的上下限肯定要平衡的，要修」「money 的设计的确不合理，虽然理论上也不该出现负数和小数」，要求先修这两点再进 P3-1c。

**① 幻兽个体值**（bug_log §21）
- 实测（esbuild 编译 `data.ts` 后统计，非正则猜测）：40 只幻兽里 38 只有 `initStatsMax`，**144 项 `initMin > initMax`**；
  `initStatsMax - base` 的差值均值 hp 4.63 / atk 2.18 / def 2.00 / spAtk 0.82 / spDef 0.79 / spd 0.50，
  而 `initMin` 硬编码 `base+3.2/2.3/2.0` —— 下限比上限高，区间整体翻转。
- 实际带宽均值 **1.6**、最窄 **0**（等于没有个体差异）。
- 隐藏最深的一层：`remapByBounds` 开头 `if (oldMax <= oldMin) return newMin`，区间反向让它**恒命中**，
  于是每次进化都把六维重置为新种族下限，**个体差异进化即清零**，不报错不告警。
- 修法：`initMin = 种族值`（去魔数），`initMax = max(initStatsMax, initMin + INIT_SPREAD_MIN=4)`。
- 平衡影响实测：30 级属性均值 139.4 → 139.6（**+0.19**），1 级均值 base+0.8 → base+2.1。零回归。
- 测试：`numericRules` 由 `t.diagnostic` 改硬断言（反向 0 / 带宽≥4 / 下限=种族值）+ `forceInitMax` 六维等于上限；
  前端新增「区间正向」「进化保差异」两条。后端 160→162，前端 47→49。

**② money 风控**（bug_log §22）
- 根因不是 money 本身，是 **code 语义粒度**：`MONEY` 用一条判断同时覆盖「非负整数格式」与「超 MONEY_MAX」，

**关键设计选择（三个都想清楚了才动手）**

1. **战斗中不写 save**。服务端每个动作只推进内存态，结算才 `commitState` 写档。
   若把下发的 HP 降/经验涨写回 `save1`，1.5s 防抖上传会立刻把战果发给服务端，
   而服务端此刻的 `expected` 还是战前摘要 → 必然 `AUTHORITY_MISMATCH` 400。
   所以 `battle.serverParty` 单独存我方战斗副本，`save` 保持战前状态直到结算快照到达。
   代价是 Arena 的 `party` / `active` 来源要改，但这是正确的那一侧。

2. **降级只在网络层失败**。`toFailure(e).transient`：无 `status` 或 5xx 才降级本地，
   4xx 一律如实报错。理由是「服务端说打不了，客户端自己打一场」会造成奖励提交被拒，
   比直接报「队伍全灭」更让人困惑。

3. **管理员测试标记上移服务端**。原先 `testShiny`/`testMaxStats`/`testOHKO` 是纯客户端作弊开关，
   战斗上移后直接失效。服务端 `start` 接受 `testFlags`，**查库确认 role==='admin'** 才应用，
   普通账号静默忽略（不报错不封号——客户端硬编码测试开关不该变成风控事件）。
   `testOHKO` 实现成「敌方开场 1 HP」，等价且不给战斗内核开后门。

**实现**

- 新增 `src/lib/battleApi.ts`：意图封装 + `toBattleState` 映射（纯函数）+ `toFailure` 归一。
- store 五入口按 `battle.serverId` 分流；`runServerBattleAction` 统一处理 pending / 错误 / 结算拉档。
- 新增 `resumeBattle`（`GET /api/battle/current`）、`leaveBattle` 未结束先 abandon。
- `importSaveJson` 加 `{ keepBattle }`，`session.ts` 传入；`BattleState` 加 `serverId/serverParty/pending`。
- 服务端：`battleView` 下发队伍完整个体 + `levelMin/levelMax`；新增 `applyAdminTestFlags`。

1. 结算快照到达时 `importSaveJson` 的 `battle: null` 把结果面板踢回空态 —— 同 §22 一样是「一个函数两种语义」。

3. `useMove` 里 `void runServerBattleAction(...)` 让 `await` 变成空操作 —— 写测试时暴露。

## P4-0 写入并发控制：CAS + 槽位锁 ✅（P4 前置）

**① 服务端 CAS**
- 新增 `backend/src/lib/revision.ts::checkWriteRevision`：缺版本 → `REVISION_REQUIRED`(400)，
