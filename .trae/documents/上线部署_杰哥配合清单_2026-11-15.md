**「正常上线」在本文的定义**：自建后端部署到云服务器，用自有域名 + HTTPS 提供 REST / WebSocket，**通过官网或私域直接分发 APK**（自己、朋友、小范围内测玩家能联网玩）。

## 3. 服务器：怎么选、多少钱、去哪买

### 3.1 为什么是 2核4G 起步

后端是 Fastify + PostgreSQL + Redis + WS 长连接（P5-1 W9 已跑通双实例）。WS 长连接常驻吃内存，2核2G 在「PG + Redis + Node + Nginx」同机部署时偏紧；Serverless 有单连接 QPS 限制，不适合长连接；家里电脑 + 内网穿透不适合长期在线。**2核4G 是本项目的最小稳妥档。**

同机自建 PG/Redis 是推荐解：PG 是权益唯一真值、Redis 只存锁/租约/TTL/临时态，同机部署零额外费用，tx 写 compose + 每日 `pg_dump` 备份即可。托管 RDS + 云 Redis 常规价约 ¥1,000–2,500/年，且轻量服务器**不支持内网互通/挂云盘**，别买「轻量 + 跨机托管 DB」这种组合。

## 7. Android 正式 keystore（自己生成，0 元，最不能丢）

**必须杰哥本机生成并保管**，tx 只读取路径与变量，不复制文件到仓库。

仓库外先建目录（PowerShell，单行执行）：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\mpk-deploy" | Out-Null
```

生成命令（用本机 JDK 21 的 keytool；不知道在哪先跑 `(Get-Command javac).Source` 定位，或直接看 `$env:JAVA_HOME`。单行，把两处 `<强密码>` 换成同一个自己记牢的密码）：

```powershell
& "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -alias mpk-release -keyalg RSA -keysize 2048 -validity 10000 -storetype PKCS12 -keystore "$env:USERPROFILE\mpk-deploy\mpk-release.p12" -storepass "<强密码>" -keypass "<强密码>" -dname "CN=MonsterPK, OU=Dev, O=MonsterPK, L=Shenzhen, ST=Guangdong, C=CN"
```

校验：`& "$env:JAVA_HOME\bin\keytool.exe" -list -v -keystore "$env:USERPROFILE\mpk-deploy\mpk-release.p12"`（会打印证书 MD5/SHA1/SHA256，TapTap 线办 APP 核准要填）。

**四个变量**（填进交接文件，不要在聊天里发）：
`MPK_KEYSTORE_FILE` / `MPK_KEYSTORE_PASSWORD` / `MPK_KEY_ALIAS` / `MPK_KEY_PASSWORD`

> ⚠️ **丢了 = 永久无法给已安装用户升级**（Android 要求同一签名），只能换包名重新发布、老用户全部丢档。请**离线备份 2 份**（U 盘 + 另一台设备），密码与文件分开存。`validity 10000` 天是为了避免证书过期。
> 本项目 `android/app/build.gradle` 已做成 fail-closed：缺任一变量直接 `BUILD FAILED`，不会产出未签名包（2026-11-15 实测）。

## 10. 交接：材料放哪、怎么通知、tx 收到后做什么

### 10.1 目录（**仓库外**，绝不入库）

```
%USERPROFILE%\mpk-deploy\  （即 C:\Users\<你的用户名>\mpk-deploy）
├── handover.md          非敏感：决策、域名、IP、备案号、进度
├── secrets.env          敏感：密码、连接串、keystore 四变量
```

1. **只读探活**：DNS A 记录是否生效、SSH 公钥能否登录、`curl /api/health`、`keytool -list` 能否读到正式证书、磁盘/内存是否够。有问题直接报，不猜。

## 11. 项目特有的 5 个坑（切云时最容易翻车）

1. **`CORS_ORIGIN` 必须精确包含 `https://localhost`**。Capacitor 正式包不带 `MPK_DEV_APK` → 默认 `androidScheme=https`（源码实证 `@capacitor/android` 的 `CapConfig.java`）→ WebView origin = `https://localhost`。漏配时 APK 的**所有** HTTP 与 WS 请求都会被拒。`backend/.env.example:33-37` 已写死这条口径；`isOriginAllowed` 是精确匹配、`*` 不是通配（2026-11-15 杰哥拍板删通配，fail-closed）。
2. **`VITE_API_BASE` 一处注入覆盖 REST + WS**：`src/lib/api.ts` 的 `API_BASE` 同时供 REST 与 `wsUrl()`（https→wss，`ws.test.ts` 已锁）。只需一个 HTTPS 域名，不要分别配 http/ws 两套。
3. **Nginx 必须透传 WebSocket Upgrade**：WS 长连接是本项目的实时主干；反代缺 `Upgrade` / `Connection` / 长 `proxy_read_timeout` 会表现为「能登录但实时状态不更新」。W9 的 `reverseProxy.mjs` 已具备该能力，生产反代照抄语义。
4. **PG 是唯一权益真值，Redis 不存权益**：同机自建时务必做每日 `pg_dump` 并异地留存；Redis 清空只影响锁/临时态，PG 丢了才是真丢档。`REDIS_URL` 一旦配置，启动必须 PING 成功否则拒绝启动（不会静默降级）。
5. **正式 keystore 与占位域名不能混**：2026-11-15 的 release 包用的是临时自签名证书 + `https://api.example.com` 占位域名，**只能验证链路，不能上线**。发布前必须用正式域名 + 正式 keystore 重出包。

补充：备案期间域名不解析到大陆服务器；域名实名主体 == 备案主体；免费证书必须自动续；轻量不支持挂云盘/VPC 内网互通，别搭配跨机托管 DB；只发 APK 无需托管前端静态站。
