# 游戏设计与可玩性补全分析

> 基于当前代码（`src/game/*`、`src/pages/*`、`src/stores/useGameStore.ts`）实际实现整理，不含未落地设想。

## 1. 现状盘点

### 1.1 内容规模

| 内容 | 数量 | 位置 |
|---|---|---|
| 幻兽物种 | 40（目标 200） | [data.ts](file:///workspace/src/game/data.ts) `MONSTER_SPECS` |
| 技能 | 294 | `MOVE_SPECS` |
| 道具 | 22 | `ITEM_SPECS` |
| 地点 | 7 | `LOCATIONS` |
| 野外区域 | 14 | `LOCATIONS[].wildAreas` |
| NPC | 17 条对话 | `LOCATIONS[].npcs` |
| 进化关系 | 22 条（全部为等级进化） | `MONSTER_SPECS[].evolutions` |

### 1.2 已实现的机制

- **战斗**：等级/攻防/特攻特防/速度、STAB 1.5、属性克制、伤害浮动 0.85–1.0、暴击 1.5、先制 priority、多段攻击、吸血、反伤、畏缩、能力阶（-6~+6）、命中/闪避阶
- **异常状态**：灼伤（物攻减半）、麻痹（速度减半 + 25% 无法行动）、睡眠、中毒、冰冻
- **行动**：技能 / 道具 / 换位（消耗一回合，敌方会行动）/ 逃跑（速度判定 75% 或 50%）
- **成长**：经验曲线 `16 + level*18`，升级加成长值，满 4 技能触发学习替换弹窗
- **进化**：等级条件 → `pendingEvolution` → 弹窗确认 → 属性按区间重映射 + HP 比例继承
- **收集**：`dexNum` 排序、`???` 占位、已发现/已捕获统计、名称模糊搜索
- **经济**：胜利获得 `50 + 等级*10` 金钱，商店购买道具，地点间移动
- **稀有度**：闪光 1%（`isShiny`），营地标记「至尊」（闪光 + 满个体 + 满成长）

### 1.3 数据字段与实际使用的偏差（需修正认知）

| 字段 | 状态 |
|---|---|
| `MoveSpec.teachable` / `exclusiveTo` | **仅声明，全项目无引用** → 技能机/教学系统未实现 |
| `ItemSpec.kind` | 只有 `capture / heal / status_heal / evolution / key_item`，**没有技能机与携带道具** |
| `NpcSpec` | 只有 `dialog`，**没有对战能力** |
| `attemptCapture().shakes` | 只写进文字日志（"摇晃 x3"），**没有摇晃动画** |
| `MoveSpec.pp` | 审计时字段不存在、技能无消耗；**已补上**，见 P0-1 |

## 2. 核心循环诊断

当前实际循环是：

```
进训练场 → 打野生怪（无消耗）→ 获得经验+金钱 → 抓怪 → 回营地 → 重复
```

三个环节都缺少"阻力"，导致中后期迅速失去目标感：

1. **战斗没有成本**：技能无限使用、HP 只要回中心就全满、金钱没有刚性支出，最优策略永远是"一直用最高威力技能"。
2. **收集没有反馈**：抓到的怪只进图鉴计数，不产生任何能力或进度收益，40 只抓完就没有下一层目标。
3. **世界没有对手**：NPC 只有对话，没有训练师战、没有关卡门槛，地点之间没有解锁条件。

## 3. 可玩性缺口（按影响排序）

### G1｜缺少资源约束，战斗策略退化（最高优先级 · 已解决）

无 PP 意味着"高威力 + 高命中"永远是唯一解，属性克制与状态技能的收益被摊薄。

已通过「技能 PP + 每场补满」解决，详见 P0-1。

### G2｜缺少阶段性目标

没有任务、成就、图鉴奖励、挑战塔。玩家的目标只有"升级"，而升级曲线是线性的。

### G3｜缺少训练师/关卡

没有 BOSS、没有道馆、没有连胜挑战，地点之间没有门槛，探索缺少"变强才可通过"的张力。

### G4｜收集驱动弱

40/200 的内容缺口 + 图鉴无任何功能奖励，收集纯粹是清单打勾。

### G5｜道具系统半成品

22 个道具里 4 个进化石 + 5 个球 + 7 个回复 + 3 个树果，缺少技能机与携带道具，`teachable` 字段空转。

### G6｜养成无差异化

同种幻兽只有成长值随机，没有性格、努力值、携带道具，导致"抓到更好的个体"之外没有培养深度。

### G7｜战斗信息呈现不足

只看得到等级与属性，看不到速度对比、先后手、能力阶变化与命中率修正，玩家难以理解"为什么这回合我先手/打不中"。

## 4. 补全方案

> 以下为设计方案，按"改动小、可回滚、不破坏现有存档"排序。

### P0-1｜技能 PP 与消耗战（已实现）

- 数据结构：`MoveSpec.pp?: number` 仅作个别特例覆盖，实际上限由 `getMoveMaxPP` 按威力推导：
  - 变化技 15；威力 ≤30 为 30、≤50 为 25、≤70 为 20、≤90 为 15、≤110 为 10、>110 为 5
- **PP 只存在战斗内**：`BattleState.ppByMonster: Record<monsterId, Record<MoveId, number>>`，战斗结束即丢弃，不写入 `SaveData`，因此不需要存档迁移
- 规则：出手前扣 1 PP；PP 为 0 时该技能禁用并提示"PP 已耗尽"；敌方同样消耗 PP，全部耗尽只能干瞪眼
- **每场战斗自动补满**：短战斗（推图 3~5 回合）几乎无感，长战斗（Boss / 未来 PvP）才是真正的资源约束
- 入口：`MoveSpec`、`BattleState`（[types.ts](file:///workspace/src/game/types.ts)）、`getMoveMaxPP`（[rules.ts](file:///workspace/src/game/rules.ts)）、[Arena.tsx](file:///workspace/src/pages/Arena.tsx) 技能按钮显示 `PP 剩余/上限`

**为什么不采用 CD**：CD 想解决的两件事分别是「自动战斗能无限循环」和「长战斗不枯竭」，前者已由挂机结算替代，后者由「每场补满 + 长战斗不补」替代。CD 与可持续回血叠加会导致 PvP 无法收敛，故不引入。

**为什么排第一**：它一次性把"技能选择"从无成本变成有成本，同时让道具与经济真正产生作用，是后续所有平衡的地基。

### P0-1b｜远征挂机与首通进度（已实现）

- 核心判断：**挂机不做战斗模拟**，只按时间结算资源，避免第二套战斗引擎与随机性
- 首通记录：`SaveData.clearedAreas`，在野外区域打赢（击倒或捕获）后写入 `{ name, level(=区域 levelMax), theme, clearedAt }`
- 派遣状态：`SaveData.idle = { areaId, areaName, level, startedAt } | null`
- 产出规则（[idle.ts](file:///workspace/src/game/idle.ts)）：
  - 金币：`分钟数 × (1.5 + 难度 × 0.15)`，难度取区域 `levelMax`
  - 捕获器：每 20 分钟一次判定，掉落率 15%；球池随难度解锁 —— Lv10+ 可掉高级捕获器，Lv20+ 可掉特级捕获器，大师球不通过挂机产出
  - 离线累积上限 8 小时，超出部分不再产出
- 入口：营地 → 地图 → 地点详情 → 「远征挂机」
- 设计意图：推图越远，可挂区域难度越高 → 金币与球的档位同步提升，形成"推图 → 挂机收益变好"的正循环

### P0-2｜图鉴里程碑奖励

- 规则：达成 `10 / 20 / 40 / 80 / 120 / 200` 捕获数时发放奖励（球、进化石、金钱、专属称号）
- 数据结构：`SaveData` 增加 `milestones: string[]`（已领取记录），`version` 递增
- 入口：营地图鉴页头部显示"下一里程碑 24/40"[Camp.tsx](file:///workspace/src/pages/Camp.tsx)；领取走 store action
- 目的：把"抓怪"从计数变成有即时反馈的正循环

### P0-3｜训练师战（最小可用版）

- 数据结构：`NpcSpec` 扩展为 `{ id, name, dialog, team?: Array<{ specId, level, moveIds? }>, rewardMoney?, defeatedFlag? }`
- 复用现有 `BattleState`：`enemy` 换成"当前在场怪"，倒地后换下一只，全部倒下即胜利
- 入口：营地地点页点击 NPC → 对话 → 「挑战」按钮；胜负写入 `SaveData.defeatedTrainers: string[]`
- 目的：提供第一个"有门槛、会失败、有奖励"的挑战，验证后续道馆/挑战塔

### P1-1｜技能机（让 `teachable` / `exclusiveTo` 真正生效）

- 数据结构：`ItemSpec` 增加 `kind: "tm"`, `moveId: MoveId`
- 规则：对队伍中幻兽使用 → 校验 `teachable` 与 `exclusiveTo` → 满 4 技能走现有替换弹窗
- 入口：营地背包使用道具；`useItemOutsideBattle` 扩展
- 收益：294 个技能中大量未被 learnset 覆盖的技能有了获取途径

### P1-2｜携带道具

- 数据结构：`MonsterInstance.heldItem?: ItemId`；`ItemSpec` 增加 `kind: "held"`
- 首批 6 个：先制之爪（10% 先手）、剩饭（每回合回 1/16）、专爱围巾（速度 x1.5、只能用一个技能）、气势头带（满血被击倒留 1 HP）、聚焦镜（暴击率 +1 阶）、抗性果（受到克制伤害减半一次）
- 入口：营地幻兽详情页增加"携带物"槽位

### P1-3｜成就与统计

- 复用 `SaveData`：新增 `stats`（总场次、捕获数、最高连胜、闪光遭遇数）与 `achievements`
- 入口：营地新增「记录」页；与 P0-2 的里程碑合并展示

### P2｜区域解锁与挑战塔

- 地点增加 `unlockRequirement`（如"击败某训练师"或"捕获数 ≥ N"）
- 挑战塔：连续战斗不回血，每 5 层给稀有奖励，作为后期目标

### G7 修正（低成本高收益）

- 战斗界面补充：速度对比箭头、当前能力阶图标、技能命中率在按钮上直观显示（已有 power/accuracy，补 PP 后为 `PP 剩余`）

## 5. 验收口径

- 每个新增系统必须满足：移动端单手可操作、关键入口 ≤ 2 次点击、不引入横向滚动
- 每次新增持久化字段必须：递增 `SaveData.version` + 在 `migrate` 中补默认值 + 旧存档可继续游玩
- 每个新机制上线前，用 `npm run check` + `npm test` 保证不破坏现有战斗规则
