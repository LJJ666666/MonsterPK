## 2. 详细条目

### F01 榜单周期结算 — ✅ 已偿还（2026-11-09）

> **实现结论**：周期 = 固定 UTC+8 自然日（`game/period.ts` 单一真源，`dayKeyOf()` 委托它）；`RankPeriodSnapshot(periodKey, boardKey)` 唯一键保证幂等可重跑；只结算**已结束**周期；7 张榜 = 四张派生榜 + 三张 Boss 伤害榜。触发方式是管理员接口或 `npm run rank:settle` 脚本（cron 可调用），不新增全局定时器。**MVP 边界**：四张派生榜按结算时刻的落库真值定格（Save 表无历史版本），生产须在周期结束点准时结算；Boss 榜按 `periodKey` 精确归档，补跑不失真。详见规范 §28。

- **来源**：杰哥 2026-11-07「周期结算、榜单奖励会有，记录好未来再设计」。
- **产品口径**：榜单不是永久累计，按周期结算（日 / 周 / 赛季待定）；结算时点、是否分组、跨周期累计规则待定。
- **当前现状**：P4-2a 四榜是**实时派生**、TTL=0 的只读读模型（`GET /api/rank/:type` 每次从 `Save` 落库真值算），无周期、无快照、无结算任务。榜单类型注册表已预留，加周期不改协议。
  **P4-2c 的 Boss 伤害榜有了「周期键」但还不是「周期结算」**：`BossDamageEvent.periodKey` 是固定 UTC+8 的 `YYYY-MM-DD`，
  查榜按 `bossId + periodKey` 过滤，所以「今日榜」天然成立；但没有结算任务、没有历史榜、没有周期结束的快照与归档。
  `periodKey` 的格式与 `dayKeyOf()` 是手算 UTC+8（不用 `toLocaleDateString`，避免宿主机时区 / ICU 差异），
  换周期粒度（周 / 赛季）只需改这一处纯函数 + 加一张快照表。
- **偿还缺口**：周期定义与服务端配置、结算任务（幂等、可重跑）、周期快照表或 append-only 事件、历史榜查询、时区口径。
- **不冲突点**：换周期快照时接口与前端零改动（P4-2a 已把读模型收口在 `modules/rank.ts`）。

### F02 榜单奖励 — ✅ 已偿还（2026-11-09）

> **实现结论**：奖励表在 `game/rankReward.ts`（服务端纯函数，前 10 名有效成绩、Boss 榜金钱 ×2，数值待杰哥拍板但不改协议）；`RankReward(periodKey, boardKey, userId, slot)` 唯一键防重复领取；发奖由服务端 `readSave → applyRankReward → 同步 authority.expected → commitState()`，**客户端没有领取入口、不能上报奖励数值**。Boss/共斗/1v1 战斗结算「刻意不发奖励」是 F01/F02 当时的事实记录；**11-09 后 F14 已偿还（Boss 双档发奖，规范 §29）、F15 冻结、F16 共斗副本设计定稿（规范 §30）**，本节其余结论仍有效。详见规范 §28~§30。

- **来源**：同 F01。
- **产品口径**：有榜单奖励，具体名次 / 奖励内容 / 发放方式待定。
- **当前现状**：P4-2a 明确不做奖励；榜单只读、无写入口。

### F04 召唤师等级：口径修正（重要） — 📋 待设计

- **来源**：杰哥 2026-11-07「召唤师等级我的初衷是，**人物的等级，跟宠物最高等级挂钩的那种。等于账号的等级**。我 10 级那么我宠物最高也只能升级到 10 级（未来可能重新设计，可能会是 N+5 级之类的想法）」。
- **产品定义（钉死，不是待定）**：
  - 召唤师等级 = **人物 / 账号等级**，是账号级真值，**不是宠物属性、不是进度派生值**。
  - **与宠物等级上限挂钩**：账号 `L` 级 → 宠物等级上限 `L`（未来可能改成 `L + 5` 之类的 N+5 规则，**规则可变，但「账号等级决定宠物等级帽」这层关系不变**）。
  - 等级帽由**服务端强制**：升级、经验结算、进化、捕获初始化等所有会改宠物等级的入口都要校验，客户端上报等级一律无效。
- **当前现状（明确标为占位偏差）**：P4-2a 实现的是**派生占位公式** `1 + 首通区域数×2 + floor(队伍等级总和/10) + 图鉴已捕获物种数`（上限 9999），见 `backend/src/game/rank.ts`。它是为了避免在四个榜单都暂定时锁死存档结构而做的临时口径，**不符合上面的产品定义**，不能当作已实现。
- **偿还缺口**：
  1. `SaveData` 增 `playerLevel`（及可能的经验值）→ **必须联动** `src/game/saveVersion.ts::SCHEMA_VERSION`、`backend/src/lib/saveValidator.ts::EXPECTED_SAVE_VERSION`、migrate 分支三处；老存档要能玩。
  2. 账号经验 / 升级规则、等级帽常量（`levelCap = playerLevel` 或 `+N` 配置化，**服务端可调**）。
  3. 所有宠物等级写入口加等级帽校验与单测。
  4. 榜单 `summoner_level` 改读真值，删掉派生占位公式。
  5. UI 文案去掉「派生」说明。
- **偿还阶段**：独立子项，建议排在 P4-2c 之前或与剧情系统合并；**不阻塞 P4-2b 房间内核**（房间层不读召唤师等级）。
- **纪律**：在此之前，任何文档 / UI 不得声称「召唤师等级已实现」；契约 §4 与后端 `RANK_META` 描述已加「占位」字样。
