## 0. 结论先行

1. **查出两个真故障**，都是「长期跳过」掩盖的：14 个浏览器冒烟整体失效（Vite 6 把 `public/_*.html` 当 SPA 入口 transform），以及 `ui_smoke_f18b` 的断言依赖已被 UI 改造移走的「回程」文案。均已修并复跑通过。

4. **补 2 个脚本 + 1 个阶段 + 2 条文档断言**：`scripts/test_inventory.mjs`（29 条静态门禁）、`src/lib/accountSwitch.test.ts`（3 条账号边界单测），门禁接入 `check:inventory`，`doc_check.py` 锁死注册与 Vite 修复。

## 2. 审核发现（逐条带证据）

### F1【真故障·影响 14 套】浏览器冒烟整体失效：Vite 6 把 `public/_*.html` 当 SPA 入口

- **取证**：本轮首次真跑 `npm run verify -- --only=smoke --strict` → `通过 0 / 失败 14`，14 套共享同一条 `[FAIL] seed 注入登录态 <!DOCTYPE html> <html lang="zh-CN">… import { injectIntoGlobalHook } from "/@react-refresh"`。日志 `.verify-logs/2026-11-15T14-51-03-851Z-p2812/`。
- **对照实验**（同一 dev server）：写 `public/_mpk_probe_test.html`，`curl http://127.0.0.1:5173/_mpk_probe_test.html` 返回带 `/@react-refresh` 的 `index.html`；同目录 `_mpk_probe_test.txt` 返回 `TXT_OK`，已存在的 `fonts/*.woff2` 返回 200 / 12512 B。**只有 `.html` 被 transformIndexHtml 接管**，不是文件路径或权限问题。Vite 版本实测 `6.4.2`。
- **顺带发现**：`vite.config.ts` 仍挂着本地存档时代的 `localSaveMiddleware`，在 dev/preview 把 `GET/POST /api/save` 读写本机 `save_data.json`。本地存档已于 2026-11-13 全删、前端与全部冒烟都带 `API_BASE` 直连 3001，全仓除该中间件外只有 `.gitignore` / `HANDOFF` / 历史日志提到该文件——是漏网旧链路。
- **修法**：删除 `localSaveMiddleware` / `localSavePlugin`，换成 `devProbeMiddleware`：命中 `^/_[\w-]+\.html$` 且 `public/` 下文件存在时，原样返回 `text/html; charset=utf-8` + `no-store`，否则 `next()`；`configureServer` 与 `configurePreviewServer` 都挂载（执行早于 Vite 内部中间件），14 个冒烟脚本零改动、生产构建零影响。
- **复验**：`curl` 临时页返回 `PROBE_OK`，首页仍 200；重跑 14 套 → **13 套全绿**，仅 F2 剩余。

### F2【真故障·1 套 4 条】`ui_smoke_f18b` 断言依赖已不存在的「回程」

- **取证**：`UI_SMOKE_F18B_RESULT pass=11 fail=4`，探针 `PROBE_DUMP` 显示 `path:"/arena"`、战斗页文本完整（`遭遇：演武堂馆主` / `选择行动` / `技能 道具 换位 逃跑`），但 `errors:["timeout:arena"]`。
- **根因**：脚本 `waitFor('arena')` 条件是 `txt().indexOf('兽域演武堂') < 0 && txt().indexOf('回程') >= 0`；而 `src/pages/Arena.tsx` 的「回程」只在**未开战空态（:138）**与**结算态（:409）**渲染，战斗进行中只有固定行动区。同样进 `/arena` 的 `ui_smoke_f18c` 用 `path() === '/arena' + 战斗特征文案`，18/18 全绿。
- **修法**：f18b 判定与断言对齐 f18c —— `/arena` + `演武堂馆主` + `选择行动`；断言名改为「战斗页显示演武堂遭遇与固定行动区（确已离开营地）」；诊断字段 `arenaReturnBtn` → `arenaActionVisible`。**没有放宽断言**，仍要求真进战斗页且 375px 无横向溢出。
- **复验**：单跑 `node scripts/ui_smoke_f18b.mjs` → `UI_SMOKE_F18B_RESULT pass=15 fail=0` / `UI_SMOKE_F18B_OK`，`arenaPath=/arena`、`arenaAction=true`、`scrollWidth2=375`。

### F3【假绿口径】服务缺失被记成 SKIP 却仍输出 `VERIFY_OK`

- **取证**：`verify.mjs` 原逻辑 `missing && !strict → status:'SKIP'`，汇总里 `skipped > 0 && strict` 才 `VERIFY_INCOMPLETE`；日常 `npm run verify` 不带 `--strict`，前端没起时 14 套冒烟静默跳过仍打印 `VERIFY_OK`。这正是 F1 能藏这么久的机制。
- **修法**：被选中却因服务未起跑不了的阶段默认判 `FAIL`，新增 `--allow-missing-services` 显式退回旧行为；显式 `--skip` / `--only` 排除的阶段根本不进入 `stages`，不受影响。汇总前打印可操作提示（`--only=check,unit,docs` / `--skip=smoke` / `--allow-missing-services`）。`--strict` 保留「有 SKIP 即 `VERIFY_INCOMPLETE`」语义。

### F4【漏跑风险】编排靠两处手工登记，无自动门禁

- **取证**：程序化解析 `verify.mjs` → `STAGES=58`、`GROUPS=check:3 unit:2 build:1 e2e:36 smoke:14 docs:2`，`UNGROUPED=[]`、`GHOST_IN_GROUPS=[]`，36 条 `e2e*` npm script 全部被引用，14 个 `ui_smoke_*` 全部登记。**当前是全对齐的**，但项目记忆里明确记过「新增阶段改两处 `STAGES`+`GROUPS`，漏 `GROUPS` 静默少跑」，靠人记不可靠。
- **修法**：把这套核对固化成 `scripts/test_inventory.mjs`，接入 `check:inventory`。

### F5【零覆盖】账号边界清理契约没有单测

- **取证**：`grep -rln "accountSwitch|signOut()" src/**/*.test.ts` 无结果；2026-11-15 真机复现的「换账号残留旧渲染副本」只有 `saveBootstrap.test.ts` 覆盖 404 清档，`accountSwitch.ts` 的 `signOut/resetAccountState` 完全裸奔。
- **修法**：新增 `src/lib/accountSwitch.test.ts`，3 条：`signOut` 停双通道 / 清 token·渲染副本·revision 基线·展示态 / **零网络请求**（锁「清不是写」）；`resetAccountState` 保留 token；退出后新账号建档不混旧副本。mock 用 spy-through（保留真实实现，避免 mock 掉被测行为的假绿）。

### F6【零覆盖】P5-3 发布构建配置只有人工取证

- **取证**：`grep -rln "MPK_KEYSTORE|usesCleartextTraffic|capacitor.config|gradle.properties" src backend/tests scripts/*.py scripts/*.mjs` → `NONE`。上一轮 release 配置（fail-closed 签名、明文分离、正式包 https scheme、CORS 示例、VITE_API_BASE）全靠 `apk_build_guide.md` 的人工清单。
- **修法**：静态门禁加 12 条断言锁死，改坏配置立刻红，不需要每次真出 APK。

### F7【死代码 / 过时注释】

- `ui_smoke_f18b.mjs`、`ui_smoke_f18c.mjs` 各有一份定义后从未调用的 `buttonInRow()`（内嵌 probe JS 里）→ 删除，断言零变化。
- `scripts/lib/edgeDom.mjs` 注释写「15 个 `ui_smoke_*.mjs`」，实际 14 → 订正；`verify.mjs` 头部「六组 E2E」→「36 套 E2E、14 套浏览器冒烟」。

### F8【误报，已排除】不要凭局部代码下结论

- `e2e_content_matrix.mjs` 尾部的 `mapBossStart()` 看似死代码，实际在 **:201** 被调用（函数声明提升），不是漏跑断言。

## 7. 后续建议

1. **不要再默认 `--skip=smoke`**：本轮证明「跳过 → 宿主行为变化 → 整套失效 → 仍显示全绿」链条真实存在；门禁已把服务缺失改判 FAIL，但只有真跑才能发现 DOM/宿主层变化。

3. 精简 `MEMORY.md` 前先跑 `python scripts/doc_check.py`（§75 教训），改 `vite.config.ts` 后必须真跑一次 `--only=smoke`。
4. UI 文案/结构调整后，同步检查依赖该文案的冒烟断言（F2 就是这么来的）；优先用路径 + 稳定结构特征，不用易变的按钮文案。
